# The Sundered Reach: project guide for Claude

A turn-based, story-heavy browser RPG in the Spiderweb Software tradition (Avernum, Geneforge, Avadon, Queen's Wish). This is Game 1 of a planned series. Owner: Jason. Full world and design doc: https://claude.ai/artifact/YVQGu9C4ys1ubYidV6PCSg. That doc is the source of truth for story and systems. This file is the short version, plus how the code works.

## Locked decisions (don't change without asking)
- **Platform:** browser game in plain HTML/CSS/JavaScript, playable on phone and desktop. No framework and no build step. (Firebase is loaded straight from its CDN as an ES module; there's still no bundler.)
- **Combat:** menu-based and turn-based, with front and back rows and no grid movement. Actions are Attack, Skill/Spell, Item, Defend, Swap Row and Flee. Turn order comes from Grace plus a little randomness, and it's shown on screen. Some enemies telegraph big attacks a turn ahead.
- **Look:** mostly rich text, with simple clickable maps for travel and locations. Torchlit-stone theme.
- **Heroes:** Kael Dunmore (Human swordsman, Varrow), Ilsa Venn (Sylvari mage, Spire Coast), Tamsin Orlo (Stoneborn healer, Hearthdeep) and Wren (half-Sylvari rogue/archer, Thornwood). Keep these names. A Vessh hero is saved for Game 2.
- **Tone:** grim but hopeful. The world is dark and choices have real costs, but the heroes can make things better.
- **Length:** about 20 hours for Game 1.
- **Signature abilities:** Kael has Last Stand, Ilsa has The Unwritten Word, Tamsin has Mend the Grey and Wren has Vanish.

## Design rules
- **Classless:** any hero can learn any skill. Race changes the cost (cheap skills are 1 point per rank, expensive ones 2) but never whether a skill can be learned.
- **Linked choices are the signature mechanic.** Every Act 1 chapter needs at least one choice that echoes into another hero's story. Echoes change *how* a problem gets solved, never *whether* it can be, so there are no dead ends. Both options must cost something.
- **World flags:** each hero's scripts can read any hero's flags but only write their own. Read another hero's flags with `otherF('hero')`.
- **Switching:** a hero can't get more than one chapter ahead of the others. XP isn't shared, but catch-up XP keeps heroes within 2 levels of each other.
- **Writing style:** Spiderweb-style paragraphs, numbered replies, and gated replies marked with their requirement. Prose should be vivid but not purple.
- **Solo fights are built around the hero's role.** For example, Tamsin wins by stalling and warding, not brawling.

## Code layout
These are plain `<script>` files that share one global scope, and **load order matters** (see `index.html`):

Signed out, or if Firebase can't load, the game saves to `localStorage` only (status `'signedout'` or `'local'`). Same interface as before (`connect`, `pull`, `push`, `flush`, `clear`, `ready`, `status`, `label`, `onStatus`) plus `signIn`, `signOut`, `onSignIn`, `canSignIn` and `canSignOut`. Also has the save-code helpers. |
| `js/firebase.js` | Loads the Firebase SDK (pinned 10.12.2 from gstatic) as an ES module **after** the plain scripts, holds the project config, and exposes `window.SR_FIREBASE` for `cloudsave.js`. The web config is public by design; the security comes from `firestore.rules`. |
| `js/core.js` | Save state (`M` is the whole save, `S` the active hero, `C` combat), helpers (`h()` for DOM), rules (`ATTRS`, `SKILLS`, `HEROES`, `ALLIES`, `BUILT`, XP table) and `save()`. |
| `js/heroes/kael/ch1.js` | The base `SCENES`, `MAPS`, `ENEMIES` and `COMBATS` (Kael's), plus the Kael and Ilsa echoes. |
| `js/heroes/ilsa/ch1.js` | Ilsa's chapter 1, added with `Object.assign` into the shared tables. |
| `js/combat.js` | Navigation (`go`, `toMap`) and the combat engine: `ACTIONS`, `ITEMS`, enemy AI, retry and step-back. |
| `js/ui.js` | Rendering, modals (sheet, journal, menu), title, hero select and chapter end. |
| `js/saves.js` | Save codes, cloud sync (`syncFromCloud`: the newer of the online and local saves wins, by `savedAt`) and `cloudBox()`, the status line with the "Sign in to sync" / "Sign out" button on the title screen and in the menu. |
| `js/heroes/tamsin/ch1.js` | Tamsin's chapter 1, her skills and actions, Bracken, and her echoes into Kael and Ilsa. |
| `js/heroes/wren/ch1.js` | Wren's chapter 1, Bows, her actions (Vanish sets `st.hidden` and `st.poised`, handled in `combat.js`), Tobin, and her echoes into the other three. Loads after Tamsin's. |
| `js/chapters.js` | The chapter system: `HEROES[id].chapters` (`{n:{title, start}}`), `chapterOf`, `chaptersDone`, `chapterLock` (no hero more than one chapter ahead: chapter n needs every other hero to have finished n − 2), `catchUp` (a hero more than 2 levels behind the leader is brought to 2 below at each chapter start), `beginChapter`, `restartChapter` and `nextStep` (what the select and chapter-end screens offer). |
| `js/party.js` | Act 2's party. `M.party` is the party's story state (shaped like a hero's: `hero:'party'`, chapter, mode, scene, map, flags, chronicle, quests, plus `members`, `rows` and the pooled `gold` and `items`); while it plays, `S` is `M.party`. | `js/heroes/<hero>/ch2.js`, `ch3.js` | Later chapters. Each loads after `chapters.js`, registers `HEROES.<hero>.chapters[n] = {title, start}`, and adds its scenes, maps, enemies and combats. |
| `js/main.js` | Start-up. |

Scene shape: `{ enter?(), view() -> {title, text:[html], choices:[{label, go?, act?, req?, tag?}]} }`. Text starting with `@echo:` renders as a cross-hero echo box. Each hero's scene IDs use a prefix (Ilsa's start with `i_`, Tamsin's with `t_`), so new heroes need their own prefix too (Wren's would be `w_`).

**New chapter pattern:** create `js/heroes/<hero>/ch<n>.js`, load it after `chapters.js` and before `main.js`, and register `HEROES.<hero>.chapters[n]`. Scene IDs keep the hero's prefix plus the chapter (`i2_` for Ilsa's chapter 2). A chapter ends the same way chapter 1 does: set `S.mode = 'end'`, `save()`, `render(true)`. The level, gear, items, companion, quests and flags carry over; flags from a later chapter add to the same `S.flags`, so echo functions can keep reading them.

**New hero pattern:** create `js/heroes/<name>/ch1.js` and load it after `saves.js` and before `chapters.js`. In it, add the hero to `HEROES` and `Object.assign` scenes, maps, enemies, combats and any new skills or actions. Define `HEROES.<name>.echoes`, then wrap the other heroes' echo functions the way `tamsin.js` does.

## Saves (don't break them)
- Save key: `sundered-reach-v2`. The save shape is `{v, cur, heroes:{kael, ilsa, tamsin, …}}`.
- Each hero's state has `chapter` (missing in older saves, which means 1) and, from chapter 2 on, `chapterSnap`: a JSON copy of the state at that chapter's start, used by "Restart chapter".
- Act 2 adds `M.party` (created when Act 2 starts; older saves simply don't have it) and `M.cur = 'party'` while the party plays. Starting Act 2 moves every hero's crowns and supplies into the party's pack. A party chapter's `chapterSnap` holds `{party, heroes}`.
- Combat units: a hero unit has `hero` (its hero id) and a companion has `allyId`; solo fights keep the ids `'pc'` and `'ally'`, party fights use the hero ids. Write new actions with `isPc(u, hero)` / `isAlly(u, id)` and read stats through `S` as usual: actions run under `asHero`.
- Never rename or remove saved fields. If the shape has to change, add a migration (see how `OLD_KEY` is handled) and bump the key only as a last resort.
- Players can move progress between devices or hosts with **Menu → save code**.
- **Cloud saves:** signing in with Google syncs the whole save `{v, cur, heroes, savedAt}` to Firestore at `saves/{uid}` as `{json, savedAt, v}`. `localStorage` is always written too, so signed-out play works fully. On start-up and on every sign-in, `syncFromCloud` keeps whichever save has the newer `savedAt` and uploads the local one if it's newer. "Erase and start over" also deletes the online save.
- **Firebase setup (console, project `sundered-reach`):** Authentication → Sign-in method → Google enabled; Authentication → Settings → Authorized domains includes `jasonmcarpenter-netizen.github.io` (localhost is there by default); Firestore Database created; Firestore → Rules = `firestore.rules` from this repo (each player can read and write only their own `saves/{uid}`). Rules changes are pasted into the console, not deployed from here.

## Working rules
- Run it locally with `python3 -m http.server`, then open http://localhost:8000.
- After any change, smoke-test by playing through each built chapter's main path, including its boss, and check for console errors. `tools/test/` automates this: load `bot.js` and `paths.js` into the game on localhost and run `await BOT.suite()` (steps in `tools/test/README.md`). It plays every chapter through both branch sets and simulates every boss. When you add a chapter, add its route and boss to `paths.js`, and add its script to `tools/test/mocktest.html` in the same order as `index.html`.
- **Balance target:** each chapter's boss should sometimes take a retry, and no single spell should end group fights in a turn or two (Arc Lightning was nerfed for exactly this).
